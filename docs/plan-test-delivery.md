# テスト配信

## 要件

- プレビューの下に「テスト配信」ボタンを置く
- 押すとモーダルが開き、メールアドレスを入力する
- 形式が不正ならバリデーションしてエラーを出す
- 入力されたアドレスへ、いま作っている内容をそのまま1通送る

## 確定した仕様（ヒアリング）

| 論点           | 決定                                                                       |
| -------------- | -------------------------------------------------------------------------- |
| 送信手段       | **Resend の HTTP API**（Route Handler から `fetch`。npm 依存は増やさない） |
| 送信元         | 環境変数 `MAIL_FROM`                                                       |
| APIキー        | 環境変数 `RESEND_API_KEY`。未設定なら送信せずエラー                        |
| ボタンの位置   | プレビュー列**上部メタ欄の右**。プレビューを閉じたら一緒に消える           |
| 宛先           | **1件のみ**。記憶しない                                                    |
| 宛先の検証     | **blur 時 ＋ 送信ボタン押下時**                                            |
| 宛先のドメイン | 制限しない                                                                 |
| 本文にエラー   | **HTML出力と同じ条件でブロック**（理由は1つだけ出す）                      |
| 件名           | 入力した件名のまま（テスト印は付けない）                                   |
| 本文           | HTML のみ（text/plain は付けない）                                         |
| POSTする中身   | クライアントで生成済みの **HTML 文字列**                                   |
| サイズ上限     | HTML **1MB** を超えたら 400                                                |
| モーダル       | ネイティブ `<dialog>` + `showModal()`                                      |
| モーダルの中身 | 宛先入力欄 ＋ 送るメールの件名                                             |
| 結果の見せ方   | モーダル内。成功したら自動で閉じ、失敗は残す                               |
| 失敗の文言     | 固定文。生のエラーはサーバーの console にだけ出す                          |

### 却下した案

- **Nodemailer + SMTP** — `dependencies` が増える。README に掲げている「実行時の追加ライブラリなし」を、
  HTTP API なら `fetch` だけで保てる
- **`MailData` を POST してサーバーで HTML を生成** — 入れ子の型を検証し直す実装が丸ごと増える。
  「プレビューと同じ物が届く」も、生成箇所が2つあると保証しにくい
- **宛先の複数指定** — 確認は1人ずつで足りる。カンマ区切りのパースと、
  「3件中1件だけ失敗した」ときの見せ方が増える
- **宛先を localStorage に保存** — 下書きと違い打ち直しの手間が小さく、
  共用端末で他人のアドレスが残る方が困る
- **送信ボタンを disabled にする** — 押せない理由を返せない（HTML出力と同じ判断）。
  ただし**送信中だけは disabled**にする。こちらは理由の提示ではなく二重送信の防止

## 設計

データの流れは `MailData` → `buildMailHtml` → **`/api/test-delivery`** → Resend。
プレビュー（iframe）とダウンロードに続く3本目の出口で、経路の分岐は `MailEditor` に閉じている。

### 判定の共有（`lib/validation.ts`）

- `isValidEmail` — 空白なし・`@` が1つ・ドメインにドット、だけを見る。
  RFC 5322 を厳密になぞる正規表現は、読めない長さになる割に
  「送れるアドレスを弾く」事故が増える。最終的な可否は送信先のメールサーバーしか知らない
- `describeBlockedReason` — 「必須の欠け → URLエラー」の順に理由を1つだけ返す。
  `MailEditor` にインラインで書いていた判定を切り出したもので、
  HTML出力とテスト配信で文言と優先順が揃う

### リクエストの検証（`lib/testDelivery.ts`）

`parseTestDeliveryRequest(input: unknown)` は、正しければ `TestDeliveryRequest`、不正なら**理由の文字列**を返す。
呼び出し側が例外処理を書かずに「文字列なら 400」で済む。

エンドポイントは誰でも直接叩けるので、画面側の検証を通ったことは前提にしない。
HTMLのサイズは**バイト数**（`TextEncoder`）で見る。日本語は1文字3バイトなので、
文字数で見ていると上限の3倍まで通ってしまう。

### Route Handler（`app/api/test-delivery/route.ts`）

このアプリで唯一のサーバー処理。APIキーをブラウザに出さないためだけに存在するので、
判定は上の純関数に寄せ、ここは受け渡しに徹する。

- 環境変数は**リクエストのたびに読む**。モジュールの読み込み時に評価すると、
  キーを持たない CI で本番ビルドが通らなくなる
- Resend の生のエラーには送信元ドメインや内部IDが混ざるため、`console.error` にだけ出し、
  クライアントには固定文を返す

### モーダル（`components/preview/TestDeliveryDialog.tsx`）

ネイティブの `<dialog>` + `showModal()`。Esc で閉じる・背景の操作を止める・
フォーカスを閉じ込める、をブラウザが持っているので追加ライブラリが要らない。

- **開いているあいだだけマウントする**。送信の状態を開き直すたびに畳み直す必要がなくなり、
  リセット用の effect を持たずに済む
- 宛先の値だけは親（`TestDelivery`）が持つ。閉じても残り、別のアドレスへ続けて送れる
- Esc とバックドロップ由来の閉じるは React を通らないので、`close` イベントで拾って親に伝える
- 成功は「送信しました」を出してから 1.2 秒で閉じる。タイマーは unmount で必ず片付ける

### 影響しないもの

- `MailData` の形は変えない（宛先は入力内容ではない）ので、`DRAFT_VERSION` は据え置き
- プレビュー列の上部メタ欄の**高さは変えていない**ため、端末枠の縮小率にも影響しない
